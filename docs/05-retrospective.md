# 复盘

最难的问题是让真实模型在不同工具观察后调整动作，同时保证输出不会因一条合法引用而夹带未经证实的断言。在线运行中，模型在正常路径读取 D03 后回答，在冲突路径读取 D01/D02 后追问，在一次读取失败后重新检索和读取。为控制最终事实表述，程序把 `answered` 的文本规范为成功读取的原文；这牺牲了回答的简洁度，但避免将模型自由表述误当作已验证事实。

开发中发现三处值得记录的行为：模型一次发出了两个检索调用，其中一个有结果、另一个无结果；若后一次覆盖候选列表，会丢失前者，因此改为合并候选。资料外问题首次被模型标记为 `incomplete`，收紧状态提示后重跑为 `needs_clarification`。Windows 控制台曾因模型查询中出现无法用 GBK 编码的字符而在打印阶段报错，改为显式 UTF-8 输出并增加回归测试。这些修改均来自实际运行观察。

下一步是改进开放式改写的召回、增加更细的语义冲突判定，以及由项目作者复核全部在线 Trace、记录个人修改和真实投入时间。当前未做企业权限、真实资料接入、部署或多 Agent。

扩展到 14 份短视频工具业务模拟文档后，20 条同源标注查询的召回虽全部命中，但 5 条无答案查询中有 3 条仍返回相关候选；这要求回答阶段明确区分“检索相关”与“证据足够”。字幕校对问答两次出现模型最终 JSON 无法解析，第三次才成功，说明在线输出仍需受约束格式或有限修复。Mock 还会机械读取无关候选，不能用它衡量证据筛选质量。下一轮应建立独立于资料编写者的真实标注集，并测答案正确率、无依据回答率和多次运行稳定性。
