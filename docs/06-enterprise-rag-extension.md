# 企业文档适配：已实现与后续工作

本项目目前有两条资料路径：原有结构化 JSON 基线，以及新增的 PDF/Markdown 本地混合检索。新增路径解析可复制文本的 PDF 和 UTF-8 Markdown，保存原文件相对路径、PDF 页码或 Markdown 标题、文档 ID、版本日期和适用范围；按父子片段切分，使用本地 Qdrant 的中文 dense 向量与 BM25 sparse 向量召回，再按 RRF 融合。同主题候选补查、原文读取、引用校验和冲突状态沿用原有 Agent。`docs/03-evaluation.md` 记录合成标注集上的实测结果。

## 当前边界

扫描 PDF 没有 OCR，会报告无可提取文本。DOCX、表格、PPTX、HTML、图片尚无解析器；索引命令会报告不支持的文件。主题、版本和范围目前来自可选 `.meta.json` 侧车，缺失时记为 `unknown`。同主题冲突扩展依赖该标注；未知主题可能漏掉冲突，不能据此声称已解决真实企业中的版本优先级。索引重建为全量操作，未做原子切换、ACL、租户隔离、删除同步或生产审计。中文向量阈值基于小型合成集选定，需在真实标注集上重新校准。

## 下一阶段设计

为 DOCX、TXT、HTML、XLSX/CSV、PPTX、扫描 PDF 分别增加解析适配器。统一输出 `document_id`、文件哈希、版本、生效时间、适用范围、权限、原文件位置、片段文本和解析置信度。表格保留行列关系；OCR 保留页图及低置信度标记。通过文件哈希与版本建立增量更新和删除同步，索引写入采用临时目录验证后原子替换。

检索阶段先按用户 ACL 过滤，再做关键词和向量召回、候选融合与重排；查询改写保留原问题和改写记录。对同一规则抽取 `{主体, 属性, 值, 单位, 适用范围, 生效时间}`，仅在适用范围和时间相交时判断是否冲突。没有明确的优先级时列出双方原文并请求确认，不按新旧日期擅自裁决。

真实落地需人工标注查询及相关片段，按格式、改写、追问和冲突分组报告 Recall@5/10、冲突双方召回率、引用定位准确率、无依据回答率、解析成功率及权限泄漏测试。当前 16 条合成查询的结果不能外推到企业语料。
