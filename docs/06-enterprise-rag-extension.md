# 面向杂乱企业文档的扩展设计（尚未实现）

当前提交只读取结构化 JSON 合成资料，以便验证 Agent 决策和冲突边界。没有文档解析、向量化或通用检索，也没有可靠的召回率指标。本页是后续工程设计，不代表现有能力。

## 可选路线与取舍

1. 直接把各类文件解析后写入向量库：原型快，但标题、版本、适用范围、权限和页码容易丢失；相似度最高的片段也可能掩盖冲突版本。
2. **推荐：先统一文档与证据结构，再做混合检索。** 把每种文件转换成带原始位置、版本、权限、解析置信度的标准片段；同时建立关键词和向量索引，合并候选后重排。工作量较大，但冲突与引用可追溯。

## 摄取与索引

第一批支持 PDF（可复制文本和扫描件 OCR）、DOCX、TXT、Markdown、HTML；第二批支持 XLSX/CSV、PPTX、图片。不同格式用独立解析适配器，不把表格逐行盲目拼成普通段落。扫描件保留 OCR 文本与原始页图；低置信度内容标记待人工核对。

解析结果统一为 `document_id`、`file_hash`、`title`、`source_uri`、`version`、`effective_from/to`、`scope`、`owner`、`acl`、`section`、`page_or_cell`、`snippet_id`、`text`、`parse_confidence`。保留原文件与解析版本，支持重新摄取、删除、去重和增量更新。按章节、段落、表格行列语义切块；引用必须能回到原文件页码、段落或单元格。

检索先做用户权限过滤，再进行关键词和向量召回，合并去重并重排。查询改写可改善口语化问法，但原始问题及所有改写查询均记录在 Trace。不能只取最相似的一条；同一主题、不同版本或适用范围的候选必须扩展检索，作为冲突检测的输入。

## 冲突与回答

从候选片段抽取可比较的结构化主张，例如 `{subject: 报销申请, rule: 提交期限, value: 30, unit: 天, scope: ..., effective_date: ...}`。只在主题、适用范围和时间相交时比较。若分别得到 30 天与 15 天，且没有明确优先级，读取双方原文、列出文档版本和位置并请求确认；不因发布日期较新就擅自裁决。只有 D01 时，可写“根据 D01，期限为 30 天”，同时说明适用范围元数据是否已确认。模型生成的主张须逐项映射到已读取证据，引用校验失败则不输出确定答案。

## 可量化评估与上线门槛

建立人工标注查询集，包含明确答案、同义改写、跨文档追问、冲突版本、资料外问题、扫描件和表格；每条标注相关片段 ID、适用范围与预期状态。报告 `Recall@5/10`（相关片段召回）、冲突双方召回率、引用定位准确率、无依据回答率、解析成功率和权限泄漏测试。按格式与问题类型分组报告，并给出样本数；当前没有这些数据，不能报百分比。

分阶段验收：先完成 PDF/DOCX/MD 的解析与来源定位，再加入混合检索和标注评测，最后接入权限、增量更新及审计。每阶段保留资料不足、工具失败和未完成状态；不能把解析失败视为“资料不存在”。
