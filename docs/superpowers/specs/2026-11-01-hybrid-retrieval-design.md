# PDF/Markdown 混合检索扩展设计

## 意图与范围

把当前只靠 JSON 主题词的知识库扩展为可摄取 PDF/Markdown 的层级检索系统，同时保留现有 DeepSeek-LangGraph 工具循环、冲突待确认、逐字引用、步数上限和 Trace。借鉴 GiovanniPasq/agentic-rag-for-dummies 的文档摄取、父子块与稠密/稀疏混合检索思路，不直接复制源码。先覆盖 PDF 可提取文本与 Markdown；扫描 PDF/OCR、DOCX、权限和增量更新明确标为后续工作。

## 方案取舍

- 整套移植参考项目：具备完整 UI/多 Agent，但引入 Ollama、较大依赖与其答案格式，难以保留本题引用和冲突边界。
- **选择性接入：** 保留本项目 Agent 和输出契约，新增摄取、父子块、Qdrant 本地索引与混合检索模块。这能独立比较新旧检索，并在笔试场景中保持可复现。
- 只加向量检索：实现较快，但中文制度中的精确数字和版本词可能被近义匹配掩盖，不满足冲突双方召回目标。

## 数据流

`PDF/MD → 页或章节原文与位置 → 父块 → 重叠子块 → 中文稠密向量 + 分词稀疏向量 → Qdrant 本地索引 → 混合 Top-k → 同主题候选扩展 → 读取完整父块 → 引用校验 → Agent 状态`。

PDF 用 pypdf 提取逐页文本，Markdown 按标题分段。父块保留完整原文、来源路径、页码/标题、文档版本、适用范围和主题；子块用于精确检索。稠密模型使用 FastEmbed 的 `BAAI/bge-small-zh-v1.5`，稀疏模型使用 `Qdrant/bm25`，中文文本先分词。Qdrant 使用本地路径持久化，RRF 合并两路结果。首次索引下载嵌入模型；不把模型权重或索引提交仓库。

资料可附同名 `.meta.json`，提供 `doc_id`、`topic`、`version_date`、`scope`。缺失字段以文件名和 `unknown` 回退，但未知 `topic/scope` 时不能宣称已经排除冲突。检索命中一条后额外扩展相同 `topic` 的候选，避免 Top-k 只返回 D01 漏掉 D02；这一步在 Trace 中明示。不同主题、只是措辞不同的资料不能凭文本差异自动裁决为冲突；现有保守校验策略暂保留并在限制中说明。

CLI 增加 `ingest` 子命令或独立模块，以及 `--index-dir` 指向已构建索引。原 JSON 资料模式保留，用于与旧评估比较。检索工具输出不改变字段名，额外增加来源位置与分数；原文读取仍返回 `doc_id/snippet_id/text`，供现有引用校验器核验。

## 验证

单元/集成测试：Markdown 与 PDF 摄取、空页和损坏 PDF、父子关联、索引重建、混合检索、D01/D02 双方召回、仅 D01 答案、引用逐字一致、工具失败和上限。构造至少 12 条标注查询计算 Recall@3/5 与冲突双方召回率，并同时运行旧主题词检索作为基线；保存数据集、实际结果和测试输出。在线 DeepSeek 至少重跑正常、冲突、资料不足、失败四条新索引路径，保存真实 Trace。不得把 Mock 或标注集成绩说成生产语料效果。

## 外部来源与许可

设计参考 [agentic-rag-for-dummies](https://github.com/GiovanniPasq/agentic-rag-for-dummies) 的 MIT 开源实现（文档摄取、父子块、混合检索）。本项目自行实现适配代码，并保留来源说明。PDF 解析选用 pypdf，避免把参考项目的整套运行时与界面带入本题。
