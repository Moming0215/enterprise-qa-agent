# 企业知识问答 Agent：设计草案

## 目标与边界

面向员工回答合成制度或产品资料中的问题。输入为问题及可选对话历史；输出为回答、文档 ID、逐字原文片段、资料缺口和任务状态。系统必须在资料冲突或不足时说明原因并请求确认，不凭空选择答案。项目以 Python CLI 运行，不接入真实企业资料。

本项目要证明模型参与下一步决策：模型可在检索、读取片段、补充检索、追问或结束之间选择；每次工具返回后再次调用模型。预设图结构只负责执行、记录和限额，不预先写死业务动作。离线 Mock 仅用于流程测试，在线 Trace 才用于证明模型决策。

不做网页、在线部署、多 Agent、企业权限管理或生产级索引。不得提交密钥、隐私数据或完整试题原文。

## 实现路线

考虑过原生 Python 循环、LangGraph 模板改造、LlamaIndex 检索组件加 Agent。选择 LangGraph 模板改造：复用模型节点、工具节点和循环骨架；业务资料、检索、引用核验、冲突处理、Trace 与测试由本项目实现。代价是框架依赖及版本兼容工作。交付文档要写明实际锁定的版本、使用功能、修改点和来源。在线模型选用 DeepSeek `deepseek-flash`，OpenAI 兼容 base URL 为 `https://api.deepseek.com`；优先使用非思考模式的工具调用，避免思考模式多轮传递 `reasoning_content` 的额外兼容问题。此模式与工具能力以实际冒烟测试确认。

## 资料与工具

- `data/` 放合成 FAQ/制度，文档包含 `doc_id`、标题、版本日期、适用范围、正文；片段有稳定 `snippet_id`。准备至少一组无冲突答案、一组同主题冲突资料、一组可支持改写查询与上下文追问的资料。
- `search_documents(query)` 返回候选片段的 ID、标题、简短摘要和匹配信息；不把摘要当作引用依据。检索实现可用轻量本地关键词/别名匹配，需说明召回边界。
- `read_snippet(doc_id, snippet_id)` 返回该片段逐字原文及元数据；工具错误返回结构化失败，不能伪装为空结果。
- 检索结果中同主题的多个候选都应交给模型核查。回答中的每条引用必须对应本次成功读取的片段，并逐字包含在原文里。程序最终校验引用 ID 和片段，校验不通过则返回未完成或资料待确认，不输出无依据结论。
- 小语料检索采用确定性的词项与同义词映射，按主题召回同组全部候选，避免只返回排名第一的文档而漏掉冲突。改写问法使用测试固定的别名；历史追问先把上一轮主题提供给模型，检索工具仍以模型传入的实际 query 工作。记录这一方案对开放表达的召回局限。

## Agent 流程与状态

CLI 读取一个 JSON 输入；LangGraph 的模型节点基于用户问题、历史和工具观察选择调用 `search_documents`、`read_snippet` 或结束。工具节点执行并记录参数、结果摘要和错误，再回到模型节点。单次运行有明确模型轮次/工具调用上限；达到上限返回 `incomplete` 与原因。

最终状态采用 `answered`、`needs_clarification`、`incomplete`。对话历史只作为消解省略指代的上下文，不覆盖资料原文。若发现版本或规则冲突且资料未注明适用优先级，列出双方原文及差异，状态为 `needs_clarification`。资料外问题须说明缺口，不编造答案。工具失败时可由模型决定重试或更换检索；耗尽上限时明确失败。

CLI 最终输出 JSON 字段固定为 `status`、`answer`、`citations`（每项含 `doc_id`、`snippet_id`、`quote`）、`gaps`、`clarifying_question`、`error`、`trace_path`。非适用字段使用空值或空列表。工具故障注入通过 CLI 参数指定一次失败的工具名，测试可复现，而模型决定是否再次调用。引用校验以完整片段中的连续逐字子串为准。

Trace 记录模型公开动作（工具名、参数或结束）、工具返回摘要、后续动作、简短决策依据、轮次和最终状态；不记录模型内部思维过程、密钥或完整 API 请求。在线与 Mock Trace 均标明运行模式、模型名称和实际执行时间。

## 六个验收场景

| 场景 | 输入与资料变化 | 预期行为与证据 |
|---|---|---|
| 明确答案 | 单一适用文档 | 检索、读取原文、引用后回答，`answered` |
| 文档冲突 | 两份文档给出不同期限，缺适用优先级 | 读取双方原文，列冲突并追问，`needs_clarification` |
| 资料外问题 | 合成语料无依据 | 补充检索或说明缺口，不编造，`needs_clarification` |
| 改写相似问题 | 同一事实的另一种问法 | 找到对应文档并引用原文 |
| 上下文追问 | 历史先问某制度，再问“那它呢” | 利用历史消解指代，仍需读取并引用资料 |
| 工具失败 | 注入一次检索或读取故障 | Trace 标明错误、模型后续动作和最终真实状态 |

至少保存 3 组真实输入、输出和 Trace，覆盖正常、资料不足、工具失败；其余场景可作为额外用例。至少两条在线 Trace 必须显示不同工具结果导致不同后续模型动作。增加资料替换实验：修改冲突文档内容后重新运行，观察引用和结论是否相应改变。

## 交付与验收

仓库包括 `README.md`、`src/`、`tests/`、`examples/`、`data/`、`docs/01-requirements.md` 至 `docs/05-retrospective.md`、依赖锁定文件和 `.env.example`。README 给出安装、在线运行、离线 Mock、测试和评审入口。评估文档逐项链接实际输出、Trace 和测试结果，区分自动测试通过与真实模型表现。

验收底线：六个场景均有可执行测试或实际记录；引用可程序校验；真实模型路径具备观察后再决策的循环；超限明确未完成；工具异常不伪装成功；文档准确记录 AI 辅助、个人贡献、实际用时和未完成部分。
