# AI 辅助与项目贡献

## 项目负责人的思路与决策

项目由负责人确定为企业知识问答方向，选择 LangGraph 组织 Agent 的模型与工具循环，并提供 DeepSeek 在线模型的接入条件。设计讨论中，负责人持续推动方案从简单问答扩展为可核对的 RAG 链路：关注企业文档格式杂乱时如何摄取资料、混合检索是否真的召回依据、冲突制度能否同时出现、引用是否逐字支持结论，以及资料不足时是否明确停下。

负责人还选定短视频工具业务作为模拟知识库场景，要求增加资料规模和问题难度，检查跨文档、冲突和无答案问题；针对在线输出不稳定、答案冗长及 README 展示效果提出多轮修改要求。这些选择决定了项目的技术重点和验收方向，也推动了后续回归测试与真实模型复测。

## AI 的具体使用范围

Codex 参与了需求整理、实现方案讨论、代码编写与修改、合成业务资料和标注查询编制、自动测试、真实模型运行记录整理，以及 README 和流程图制作。实现包括 PDF/Markdown 摄取、父子分块、Qdrant 本地索引、中文语义向量与 BM25 混合检索、LangGraph 决策循环、引用与冲突校验。仓库中的测试结果和 Trace 由 Codex 使用本地命令生成，命令与输出均已留档，便于负责人独立复核。

负责人指定参考 [agentic-rag-for-dummies](https://github.com/GiovanniPasq/agentic-rag-for-dummies) 后，项目借鉴其父子分块和 dense/sparse 检索思路，结合本项目的工具接口与证据校验要求重新实现；未复制其源文件。流程图视觉审查参考 [Unslop by Damir Sokolovsky](https://github.com/heydamir/unslop)（CC BY 4.0），在保留原有流程内容的基础上调整图标、配色和排版。

## 讨论、验证与修正

负责人明确要求用实际工具结果检验 Agent 决策，并多次追问“只检索到冲突一方怎么办”“引用正确但答案无依据怎么办”。因此项目保存了正常回答、资料冲突、资料不足、工具失败和步数耗尽等路径的输入与 Trace。当前自动测试为 **52 passed**；[评估记录](03-evaluation.md)列出检索指标、在线结果及其限制。

真实运行也暴露了问题：模型曾输出无法解析的 JSON，接口曾返回 HTTP 503；提交前复测又发现同一文档的多个片段被误判为相互冲突。Codex 根据这些观察加入格式修复、回归测试和按文档 ID 判断竞争资料的修正。当前版本在 16 次工具调用上限下保存了正常、冲突、资料不足三条在线成功路径；一次 8 次上限耗尽也如实保留。小样本运行不能证明长期稳定性。
